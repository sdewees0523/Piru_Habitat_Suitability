This file documents every data file in data/raw_data/, data/clean_data/, and
data/models/: what it contains, its columns and their units, and the
conventions used across files (species codes, plot IDs, time, mortality
coding, scaling). See README.md for the script pipeline that produces each
file. See the manuscript Methods and Appendices S1-S5 for full field and
laboratory protocols.

Status note: most units and values below were confirmed by directly reading
the data files. A small number of items could not be determined this way and
are marked [CONFIRM] with the specific question that needs an answer from the
data collector.

1.2 Field-sheet species labels

  The raw "Plant" column carries a flagging-tape colour with the code, e.g.
  "ENCA (Pink)", "SAME (Orange + Pink)". These where initially created to guide experimental set up/planting and thus are stripped in 1.2.

1.3 Plot identifier

  "ID" in the raw field sheets; "plot_number" (or "plot") from 1.2 onward.
  One plot = one planting location = at most one seedling. Values are
  non-contiguous integers, roughly 1-1700. This is the join key linking
  survival, growth, microclimate, and topography data.

1.4 Time

  - start_date / end_date: calendar dates bounding a census interval.
  - start_time / end_time: DAYS SINCE THAT INDIVIDUAL'S PLANTING DATE, not
    calendar days and not days since a common origin. end_time is the
    response variable passed to survival::Surv().
  - Planting was staggered across individuals, so two rows with the same
    end_time value are not necessarily the same calendar date.

  Census dates: planting (rolling, Jan-Feb 2020), watering visit 2
  (~May 2020), measuring (Jun-Jul 2020), measuring_2 (Oct-Dec 2020),
  measuring_3 (Nov-Dec 2021). Seasonal model cutoffs used throughout the
  pipeline: 2020-05-30 (early/late spring split), 2020-06-26 (planting-window
  end), and 2020-09-30 (summer/fall split).

1.5 Mortality and censoring

  "dead": 0 = alive, 1 = dead at the end of the census interval.

  A transient value of 2 exists ONLY inside 1.2's intermediate computation,
  marking a gopher-attributed loss; those rows are censored and dead is reset
  to 0 before the file is written.

  "gopher": 0/1 flag on output files. 1 = the census note for that
  plot/date indicated gopher activity. Trigger strings are hard-coded per
  census file (see section 2.3 below).

 1.6 Scaling

  Nothing in data/clean_data/ is scaled. All scaling happens at analysis
  time in 2.3, 2.4, and the 3.x visualization scripts:

    Variable                          Scaling
    les_1, les_2, wood_density        scale() across the 9 modelled species
    wue                               scale(), then multiplied by -1 (see 3.7)
    temperature, vpd                  scale() WITHIN DATE (group_by(date))
    height, planting_height,          scale() across all individuals
      july_height
    soil_moisture                     already within-date centred upstream
                                       (see predicted_environmental.csv,
                                       section 3.6); not re-scaled

3.5 temperature_measured.csv, humidity_measured.csv

  Sub-daily iButton records, all download batches concatenated.

    Column          Type    Units
    plot            int     Plot number (parsed from source filename)
    date            date    Date
    time            chr     Time of day (lubridate period string, e.g.
                            "5H 29M 0S")
    temperature     num     degrees Fahrenheit (all batches normalised to F,
                            regardless of the units originally logged)
    humidity        num     Relative humidity, % (clamped to [0, 100] in 1.4)

  1.4 applies QC (drops records above the station's daily max + 10 deg F, as
  probable sensor overheating), then reduces each to a DAILY MAXIMUM per
  plot before computing vapor pressure deficit:

    svp = 610.78 * exp( T / (T + 237.3) * 17.2694 )     [Pa]
    vpd = svp * (1 - RH/100) / 1000                     [kPa]

3.6 predicted_environmental.csv

  Random-forest-predicted microclimate at every GPS'd planting location,
  daily. This is THE environmental input to every survival and growth model
  in the manuscript.

    Column          Type   Units / notes
    plot_number     int    Plot ID
    date            date   Daily, 2020-04-03 to 2020-12-03
    soil_moisture   num    Predicted WITHIN-DATE Z-SCORE of VWC - unitless,
                           NOT absolute soil moisture.
    temperature     num    Predicted daily maximum temperature, degrees F
    vpd             num    Predicted daily maximum VPD, kPa

  Predictors (see soil_rf.rds / temp_rf.rds / vpd_rf.rds in section 4): the
  13 topographic variables listed in section 3.9, plus date and the
  station's observed daily maximum temperature. Note the column units are
  heterogeneous (a z-score, degrees F, and kPa side by side) because this
  file is a direct model output; 2.3 and 2.4 subsequently re-standardize
  temperature and vpd within date before model fitting, bringing all three
  onto comparable scales for modelling purposes.

3.7 plant_traits_clean.csv

  Species-level trait means, one row per species (10 rows).

    Column                Type   Units
    species               chr    Species code
    sla                   num    Specific leaf area (mean leaf area / dry
                                 mass per leaf), mm^2/g [divide by 100 for
                                 cm^2/g]
    ldmc                  num    Leaf dry matter content (dry mass / wet
                                 mass), g/g
    leaf_thickness        num    Derived proxy = 1 / (sla * ldmc); NOT a
                                 direct measurement
    percent_n             num    Leaf nitrogen, % dry mass
    percent_c             num    Leaf carbon, % dry mass
    c_n                   num    Carbon:nitrogen ratio, unitless
    wue                   num    See below
    wood_density          num    g/cm^3 (NA for HEWH - see section 2.7)
    petiole_length        num    mm (from leaf_other.csv, literature-derived)
    leaf_lamina_length    num    mm ( " )
    leaf_width            num    mm ( " )

  WUE - READ THIS BEFORE USING THIS COLUMN. It is computed as:

    wue = (-8 - d13c) / (1 + d13c/1000)

  which is carbon isotope discrimination (delta-13C), in per mil, assuming a
  source-air delta-13C of -8 per mil. HIGHER discrimination means LOWER
  water-use efficiency - the opposite sign convention from what the column
  name suggests. This is why the manuscript's trait table caption specifies
  that smaller values indicate higher WUE, and why every downstream model
  script (2.3, 2.4, 3.5) multiplies the scaled variable by -1 before it
  enters a model, so that a larger value in the FITTED MODELS means genuinely
  higher water-use efficiency. Anyone using plant_traits_clean.csv or
  cox_plant_traits.csv directly, without that sign flip, will get water-use
  efficiency backwards.

--------------------------------------------------------------------------------
4. data/models/  -  fitted model objects and model-selection tables
--------------------------------------------------------------------------------

4.1 soil_rf.rds, temp_rf.rds, vpd_rf.rds

  Random forest objects (class randomForest.formula) predicting daily soil
  moisture, temperature, and VPD respectively from the 13 topographic
  variables (3.9) plus date and station daily-max temperature. Used by 1.4
  to build predicted_environmental.csv (3.6); performance metrics are
  reported in Appendix S2.

  NOTE ON FILE EXTENSION: these three files are written with R's save()
  (native .rda/.RData format) but carry a .rds extension. They must be
  loaded with load(), not readRDS() - attempting readRDS() on these files
  will fail.

4.2 early_spring_model.rds, summer_model.rds  (survival models)

  Final Cox proportional-hazards models (class coxph), built by
  2.3.1_trait_model_creation.R from the delta<2/min-df dredge selection
  performed in 2.3 (see 4.5 below). Also .rda-format files with a .rds
  extension (see note in 4.1).

  Actual fitted formulas:

    early_spring_model:
      Surv(end_time, dead) ~ height + les_1 + les_2 + soil_moisture + vpd +
        wood_density + wue + height*les_1 + height*les_2 + height*wue

    summer_model:
      Surv(end_time, dead) ~ height + les_1 + soil_moisture + vpd + wue +
        height*les_1 + les_1*vpd

4.3 late_spring_growth_model.rda, late_summer_growth_model.rda

  Final linear growth models (class glm), built by
  2.4.1_growth_model_creation.R from the corresponding filtered dredge
  tables (4.6).

  Actual fitted formulas:

    late_spring_growth_model:
      growth ~ les_1 + les_2 + planting_height + les_1*planting_height

    late_summer_growth_model:
      growth ~ les_2 + temperature + wood_density + wue

4.4 dredge_tables/  -  model-selection intermediate tables

  Written by 2.3 (survival) and 2.4 (growth). Each file is the output of
  MuMIn::dredge() over a global model containing all pairwise trait x
  environment interactions for one candidate time window, filtered to
  models within 2 AICc units of the best model, then to the model(s) with
  the fewest parameters among those.

    Survival window tables            Growth window tables
    spring_all_dredge_filtered.csv    growth_spring_all_dredge_filtered.csv
    early_spring_dredge_filtered.csv  growth_early_spring_dredge_filtered.csv
    late_spring_dredge_filtered.csv   growth_late_spring_dredge_filtered.csv
    summer_all_dredge_filtered.csv    growth_summer_all_dredge_filtered.csv
    summer_dredge_filtered.csv        growth_late_summer_dredge_filtered.csv
    fall_dredge_filtered.csv          growth_fall_dredge_filtered.csv

  Columns (standard MuMIn dredge output): one column per candidate term
  (survival tables carry height, les_1, les_2, soil_moisture, temperature,
  vpd, wood_density, wue, and all their pairwise interactions; growth tables
  substitute planting_height or july_height for height), containing that
  term's coefficient where it was retained in a given candidate model and
  blank/NA where it was dropped, followed by summary columns df, logLik,
  AICc, delta, and weight. "(Intercept)" is written as a column header.

  2.3.1 and 2.4.1 read these filtered tables and build each final model's
  formula programmatically from whichever term columns are non-NA.

  Not every window's filtered table produced a final saved model - see
  section 4.2/4.3 for which window (early_spring vs. spring_all vs.
  late_spring, etc.) was ultimately used for each season's reported result.
